# Model Miniaturization Experiment

このブランチだけで進める、Scratch上でのひらがな拡散モデル推論実験です。リポジトリ本流の多フォント・組合せ汎化実験とは分離します。

## 成功条件

最初の目標は高品質なフォント再現ではありません。

- 通常のScratchプロジェクト内だけで推論する
- 重みを1つのリストへ格納できる
- 総パラメーター数を200,000未満にする
- 64×64グレースケール画像を生成する
- 破綻が残っても、ひらがなとして認識できる
- 拡散モデルとして複数ステップでノイズから画像を生成する

## 第1実験：73,721パラメーター

| 項目 | 値 |
|---|---|
| 画像サイズ | 64 × 64 |
| 学習画像 | 9フォント × 46文字 × 100変形 = 41,400枚 |
| 文字条件 | 46 |
| フォント条件 | 9 |
| timesteps | 1,000 |
| 学習エポック | 100 |
| 学習方式 | ε予測によるConditional DDPM |
| 推論方式 | 50-step DDIM |
| base channels | 8 |
| channel multipliers | 1, 2, 3 |
| condition dimension | 32 |
| 総パラメーター数 | 73,721 |
| 上限に対する使用率 | 約36.9% |
| 最終loss | 0.033445 |

画像サイズはパラメーター数に直接影響しませんが、畳み込みの演算回数と中間特徴量には大きく影響します。この実験では品質を優先して64×64を維持し、チャンネル数と演算を削減します。

## Scratch向けに制限した演算

studentモデルは次の演算だけで構成します。

- 通常の3×3畳み込み
- 1×1 skip畳み込み
- ReLU
- 平均プーリング
- 最近傍拡大
- 特徴マップの加算と結合
- Embeddingと全結合

標準モデルで使用していた次の演算は含みません。

- GroupNorm
- SiLU
- ConvTranspose2d
- sinusoidal timestep embedding

時刻条件は、Scratchでsin/cosを毎回計算せずに済むよう、学習可能な1,000×32のEmbeddingとして保持します。

## 第1実験の結果

100エポックの学習後、通常重み（raw）とEMA重みを同一seed・50 stepsで生成して比較しました。

- 一部に文字らしい筆画は現れた
- 背景ノイズを十分に除去できず、線の途切れや大きな黒い塊が残った
- ひらがなとして安定して認識できるという最低成功条件を満たさなかった
- 同じ文字に対する9フォントの出力がほぼ同じで、フォント条件を十分に利用できなかった
- rawとEMAの両方が同様に破綻したため、EMAの追従不足ではなくモデル本体の表現力または構成上の問題と判断した

最終lossも9フォント基準モデルの0.005915に対して0.033445と大きく、同じ構成のまま学習時間だけを増やす実験は行いません。

生成結果の一覧は次の2枚を保持します。

- `outputs/miniature-64/samples/raw/seed-20260730-steps-50/grid.png`
- `outputs/miniature-64/samples/ema/seed-20260730-steps-50/grid.png`

完全チェックポイントは再利用せず、容量節約のため削除します。

## 失敗原因の仮説

73,721という総数だけでなく、Scratch向けに単純化した方法に問題があった可能性があります。

- 8/16/24チャンネルでは、64×64のノイズ除去と文字・フォント条件の両立に容量が足りない
- 正規化をすべて除いたため、時刻ごとに大きく変わる入力分布を扱いにくい
- ReLUが負の中間表現をすべて0にするため、正負を持つノイズ予測に不利
- 1,000×32の学習可能な時刻Embeddingだけで32,000パラメーターを消費している
- 各時刻を独立したIDとして学習するため、近い時刻同士の連続性をモデルへ明示できていない

## 第2実験の方針

64×64、200,000パラメーター未満、Scratchで再現可能な演算という条件は維持し、上限をより有効に使います。

- チャンネルを16/32/48へ増やし、総数166,657（上限の約83.3%）とする
- 時刻条件をパラメーター不要のsin/cos表現へ戻す
- Scratchでは使用する推論時刻のベクトルを事前計算した定数として持たせる
- ReLUをLeakyReLUへ変更し、負の中間表現を残す
- 学習時にBatchNormを使用し、推論用書き出し時に係数を畳み込みの重みとbiasへ統合する
- 平均プーリングと最近傍拡大は維持する
- まず通常のDDPM lossで単体の生成能力を確認し、不十分なら4.75M teacherから蒸留する

第2実験でも、学習開始前にGPU使用、予想時間、出力先を確認します。

実装時点の設定は次のとおりです。

| 項目 | 値 |
|---|---|
| 画像サイズ | 64 × 64 |
| base channels | 16 |
| channel multipliers | 1, 2, 3 |
| condition dimension | 48 |
| 総パラメーター数 | 166,657 |
| 上限に対する使用率 | 約83.3% |
| 出力先 | `outputs/miniature-v2-64` |

## 未解決の制約

200,000パラメーター未満でも、Scratchで十分速いとは限りません。特に64×64の畳み込みと複数回のU-Net実行が主なボトルネックです。

最初の実測後、必要に応じて次を検討します。

- depthwise separable convolution
- チャンネル数の追加削減
- 中間解像度の削減
- 4-stepまたは1-stepへの蒸留
- 整数量子化
- TurboWarpでの比較

32×32化は最初から採用せず、64×64で認識可能性と実行時間を確認した後の退避案とします。
